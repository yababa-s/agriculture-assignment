# Evaluation

All numbers on this page are generated by `scripts/make_eval_report.py` from `eval/results/*.json`.

## 1. Evaluation design

| Set | Source documents | Size | How the reference was made | Used in training? |
|---|---|---|---|---|
| Island extraction gold | D10 (2024-25) | 31 islands, 294 items | rule extractor output checked line by line against page text | **No** |
| Column-mapping gold | D02, D06 | 11 prompts, 74 columns | rule-resolved specs, D02 checked against rendered page | **No** |
| Routing gold | all 20 files | 20 | manifest source group (human-assigned in Phase 1/2) | No (router not fine-tuned) |
| Direct value checks | D01, D02, D05, D07, D10, D12, D13, D15, D16, D17 | 48 values | read by eye from rendered pages | No |
| LoRA training set | D08, D09 islands; D01, D03, D04, D05 tables | 84 train + 9 valid | rule-labelled (silver) | — |

Split is by **document** (`data/splits/splits.json`). `scripts/build_datasets.py` asserts that no eval-island text appears in the training files. D06 (bilingual, non-English), D10 and D13 (raster-ruled) contribute nothing to training and are used as the unseen-document demo set together with instructor files.

**Acceptance criteria (set before running):** value_checks ≥ 0.95, groundedness ≥ 0.99, routing_manifest ≥ 1.0, routing_llm ≥ 0.8, island_f1_gated ≥ 0.8, column_accuracy ≥ 0.8, json_valid ≥ 0.95, automation ≥ 0.9.

* **Intent Resolution**: no user intent in Phase 2 (batch extraction); evaluated in Phase 3 query agent

* **Code vulnerability / Ungrounded attributes**: no generated code; no person-level attributes are extracted (no PII by design)

## 4. Automation

* Inputs completed without manual intervention / inputs attempted: **20/20 = 1.0**
* Manual interventions during the run: 0
* Retries triggered by the validator: 0; LLM calls: 531; model outputs rejected by gates: 157; duplicate rows skipped: 127
* Needing review or failed: none
* Manual steps that remain outside the run, each done once:
  * source discovery and download (Phase 1)
  * recording download URLs in the source registry (once per file)
  * reviewing gold sets
  * deciding the source group of each corpus file (unseen files are routed automatically)
* Remaining barriers to automation:
  * chart-only atlas pages (D18) need chart digitisation
  * raster maps are out of scope by brief
  * an instructor file with a new price layout would rely on LLM column mapping
  * no robots.txt-aware downloader yet: Phase 1 files were fetched by hand

## 5a. Robustness: unseen file types (scans, photos, Unicode Hindi)

Built by `scripts/make_test_unseen.py` from corpus pages, so the correct values are known; run as UNSEEN files (no manifest) by `experiments/robustness_unseen.py`. Precision = extracted values equal to a known value; recall = known values recovered.

| T2 photo of a price table | price_table_agent | yes | 1.0 | 0.104 | vision |
| T3 Unicode Hindi table | matrix_table_agent | yes | 1.0 | 1.0 | — |
| T4 scanned bilingual Hindi page | bilingual_table_agent | yes | 0.545 | 0.263 | vision(digits)+easyocr(hi) |
| T5 map image | skip | yes | — | — | — |
| T6 Hindi PDF with broken text layer | bilingual_table_agent | no (matrix_table_agent expected) | 0.692 | 0.477 | vision(digits)+easyocr(hi) |

Reading: digital Unicode Hindi is solved; scanned English tables are mostly right when read; photos, scanned bilingual pages and broken Hindi text layers work end to end but miss many values (OCR reading accuracy, not routing, is the limit). Numbers checked by `check_unseen.py` are compared with the OCR text layer, so for scans they show what was read, not whether the OCR read it correctly: compare a few by eye.
